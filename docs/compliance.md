### A-01 · კალენდრის სინქრონიზაციის აგენტი

**კოდი:** `lib/ical/run-sync.ts`, `lib/ical/sync.ts`, `lib/ical/parse.ts`, `lib/ical/url-guard.ts`

**რას აკეთებს.** ერთეულის თითოეული არხის iCal ფიდს ჩამოტვირთავს,
დაშლის RFC 5545-ის მიხედვით და ჯავშნებად აქცევს. „არ არის ხელმისაწვდომი"
ტიპის ბლოკები გამოტოვებულია. დუბლიკატი იჭრება `unitId + source +
externalId`-ზე, ამიტომ ხელახალი სინქრონიზაცია განაახლებს და არ გაამრავლებს.

**რა ამოძრავებს.** სამი გზა: `/units`-ის ღილაკი „კალენდრების სინქრონიზაცია";
`POST /api/sync` (სესიაზე მიბმული, cron-ისთვის); ლოკალური განრიგი
`SYNC_INTERVAL_MINUTES` ინტერვალით (ნაგულისხმევი 60 წუთი).

**რა მონაცემს ეხება.** ჩამოსვლა-გამგზავრების თარიღები, ღამეების
რაოდენობა, თანხა, არხის UID და — თუ ფიდში არის — **სტუმრის სახელი**.
ეს ერთადერთი პერსონალური მონაცემია და ის არასავალდებულოა: ჯავშანს
მხოლოდ წყარო, თარიღები და თანხა სჭირდება.

**რითია დაცული.**

| დაცვა | სად |
|---|---|
| **SSRF-ის ბლოკი** — მისამართს ოპერატორი წერს, სერვერი კი ითხოვს. მხოლოდ https (ლოკალურად http), აკრძალულია loopback, link-local (`169.254.169.254` — ღრუბლის metadata), RFC 1918, CGNAT, IPv6 ULA/link-local, IPv4-mapped, ლოკალური სახელები | `url-guard.ts` |
| **გადამისამართების შემოწმება** — `redirect: "manual"`, შემდეგ იგივე შემოწმება; მეორე hop-ზე `redirect: "error"` | `run-sync.ts` |
| **URL-ში ჩაშენებული credential-ის უარყოფა** — თორემ ის შეცდომის ტექსტში მოხვდებოდა | `url-guard.ts` |
| **15 წამიანი ტაიმაუტი** | `AbortSignal.timeout` |
| **ფიდის იზოლაცია** — ერთი ფიდის შეცდომა სხვას არ აჩერებს | `syncAllUnits` |
| **დამოკიდებულების გარეშე პარსერი** — არც `eval`, არც გარე ბიბლიოთეკა | `parse.ts` |
| **API სესიაზეა მიბმული** — `/api/sync` სესიის გარეშე 401-ს აბრუნებს | `app/api/sync/route.ts` |

### 7.1 რატომ არის საჭირო

არ ხურავს: ხელშეკრულებით მანქანა კონკრეტულ მძღოლზეა და კოორდინატი მისია.

# English version

## 1. Scope and roles

**In scope:** the Next.js application, the database, the automated agents
(§2), the external integrations (§5), the source repository.
**Out of scope:** operators' own devices, the GPS gateway (customer-side),
operators' WhatsApp accounts, the channels' internal systems.

**Roles — the most important distinction in this document:**

| Data | Controller | Processor |
|---|---|---|
| Operator account: email, name, plan, payments | **Activo** | — |
| Audit trail, sessions, security records | **Activo** | — |
| Tenant / driver name and phone, contracts | **Operator** | Activo |
| Driver location, geofence events | **Operator** | Activo |
| Guest name on a booking | **Operator** | Activo |

The operator is answerable for whether they have a lawful basis to track a
driver, whether the contract sets out the "red lines", and whether the
driver was told. Activo supplies the instrument and is answerable for the
instrument being safe, touching minimal data, and doing nothing outside the
operator's instructions.

> ⚠️ **Open item `O-04`:** this split currently lives only in this
> document. It must also be in the contract (GDPR Art. 28). Until the
> Terms of Service carry a processor agreement, this is a live risk.

| A-02 | Pricing engine (rules) | button / schedule | none | no |

**The points a reviewer should not have to dig for:**

- **A-03 sends no personal data.** Unit name, district, city, rates,
  seasonality factors and reason codes — nothing else. And the model never
  sets a price: the number comes from the deterministic engine (A-02) and
  the model only writes the sentence explaining it. No automated
  decision-making with legal effect (GDPR Art. 22).
- **A-05 records only zone changes**, not a continuous track. A car parked
  one street past the line pings every minute; one row is written and the
  owner is told once. `GpsDevice` holds the *last* position, never a
  history. Location events are deleted after 90 days.
- **A-06 skips any contract with no `paidThrough` date.** An old lease
  entered before schedule tracking existed would otherwise be announced as
  a year overdue — a false accusation, because the money that was paid was
  simply never recorded. Fairness (GDPR Art. 5(1)(a)) implemented in code.
- **A-07 has a mode in which nothing reaches Meta at all**: without Cloud
  API credentials the message waits in the outbox behind a `wa.me` link
  that the operator sends from their own account.
- **A-08 never trusts the browser redirect.** The signature is verified and
  the amount cross-checked against the stored order before a plan is
  activated, and the handler is idempotent. Card data never touches the
  application (hosted checkout → PCI DSS SAQ A profile).
- **A-10 stores no copy of the data.** Pseudonymous actor reference,
  truncated IP (/24, /48), counts only. A trail that repeats a phone
  number doubles the exposure it exists to document.
- **A-11 is not a language model.** Deterministic keyword matching over a
  six-entry FAQ, entirely client-side. Nothing typed into it is sent,
  stored, or shared — and it must not be described as an AI chat.

Full per-agent detail, including the specific defences and where they live
in the code, is in the Georgian section §2 above.
